# GongMoa · 공모아

**나에게 필요한 대학 공지를 모으고, 준비부터 마감까지 함께 관리하는 앱.**

ENDPoinT 해커톤 2026 **Team 15**의 서울과학기술대학교 맞춤 공지 서비스입니다. 여러 게시판의 공지를 한곳에서 확인하고, AI가 정리한 핵심 내용과 지원 조건을 살펴본 뒤 관심 저장·준비물 체크·마감 알림까지 이어갈 수 있습니다.

## 1. 왜 공모아인가요?

대학 공지는 매일 올라오지만, 나에게 맞는 기회를 찾으려면 긴 본문을 읽고 지원 조건과 일정을 직접 확인해야 합니다. 관심 있는 공지를 저장해도 준비물이나 신청 마감을 놓치기 쉽습니다.

공모아는 **공지 발견 → 조건 확인 → 관심 저장 → 준비 → 신청 완료**를 하나의 흐름으로 연결합니다.

## 2. 주요 기능

| 기능               | 할 수 있는 일                                                                 |
| ------------------ | ----------------------------------------------------------------------------- |
| 맞춤 공지          | 학과·학년·학적 상태와 관심 키워드를 바탕으로 관련 공지를 확인합니다.          |
| 실제 게시판 수집   | 서울과기대 대학공지사항과 컴퓨터공학과 학부 공지사항을 모아 봅니다.           |
| AI 핵심 정리       | 공지의 요약·지원 조건·일정·준비물을 확인하고 원문으로 이동합니다.             |
| 관심 공지 관리     | 공지를 저장하거나 넘기고, 준비 중·신청 완료 상태를 관리합니다.                |
| 준비물 체크리스트  | 신청에 필요한 항목을 체크하고 진행 상황을 남깁니다.                           |
| 캘린더와 마감 알림 | 저장한 공지의 확정된 일정을 확인하고 Android 마감 알림을 받습니다.            |
| 기기 내 저장       | 프로필·키워드·관심 공지·체크 기록을 SQLite에 보관해 재실행 후에도 이어갑니다. |

AI 분석에서 확인되지 않은 정보는 원문을 통해 확인할 수 있도록 표시합니다. 수집이나 분석에 실패해도 저장한 공지와 진행 기록을 유지하고, 다시 시도할 수 있습니다.

## 3. 사용 흐름

1. **내 정보 설정** — 첫 실행에서 단과대학을 고른 뒤 해당 학과·자유전공학부를 선택하고, 학년·학적 상태와 관심 키워드를 설정합니다.
2. **공지 가져오기** — 설정에서 AI 시연 토큰을 등록하고 맞춤 공지를 새로고침합니다.
3. **나에게 맞는 공지 발견** — 분석이 완료된 공지의 요약과 조건을 살펴봅니다. 전체 공지 보기로도 탐색할 수 있습니다.
4. **관심 저장과 준비** — 관심 있는 공지를 저장하고 준비물 체크리스트를 채웁니다.
5. **마감 확인과 신청** — 캘린더와 알림으로 일정을 챙기고, 원문의 신청 안내를 따라 신청한 뒤 완료로 표시합니다.

앱은 **메인·맞춤 공지·휴지통·설정**의 네 화면으로 구성됩니다. 프로필과 키워드는 설정에서 변경할 수 있으며 자동 저장됩니다.

## 4. 기술 구성

| 영역        | 기술 및 역할                                                      |
| ----------- | ----------------------------------------------------------------- |
| 모바일 앱   | Expo SDK 58, React Native, React, TypeScript, Expo Router         |
| 데이터 저장 | Expo SQLite로 공지·프로필·진행 상태 저장                          |
| 기기 기능   | Expo Notifications로 알림 예약·취소, SecureStore로 기기 토큰 보관 |
| 공지 수집   | 모바일에서 공개 게시판 HTML 수집·정규화                           |
| AI 분석     | Cloudflare Workers에서 Gemini 호출, 인증·호출 제한·응답 검증      |
| 공통 계약   | Zod 스키마로 수집·분석·앱 사이의 데이터 검증                      |
| 검증        | Node 테스트 러너, Playwright, Android 실기기 확인                 |

공지 수집과 개인화는 앱에서 수행하고, AI 호출은 Worker를 거칩니다. Gemini API 키는 서버 비밀 설정에 보관합니다.

## 5. 실행하기

[.nvmrc](.nvmrc)에 고정된 **Node.js 24.22.3**을 사용합니다.

```sh
nvm install
nvm use
npm ci
npm run start
```

PC와 Android 기기를 같은 네트워크에 연결한 뒤, SDK 58을 지원하는 Expo Go에서 QR 코드를 열어 실행합니다. 에뮬레이터에서는 `npm run android`, 브라우저 미리보기는 `npm run web`을 사용합니다.

실제 AI 분석에는 팀의 유효한 시연 토큰이 필요합니다. 앱의 **설정 → AI 분석 설정**에서 등록하며, Android에서는 SecureStore에 저장합니다. API 키와 토큰을 소스 코드나 `EXPO_PUBLIC_*`에 넣지 않습니다.

Worker를 직접 실행하려면 먼저 `npm run worker:setup`으로 로컬 설정 파일을 만들고 Gemini 키와 모델을 설정합니다. 자세한 설정·배포 절차는 [개발·운영 가이드](docs/campus_notice_development_guide.md)에 있습니다.

```sh
npm run worker:dev
```

## 6. 검증과 구현 현황

실제 두 게시판 수집, 배포 Worker의 Gemini 분석, SQLite 저장·재실행을 연결했습니다. Android 통합 흐름과 변경·실패·알림 검증은 **2026-11-14 사용자 확인**으로 기록되어 있습니다. 새 초기 설정 화면의 Android 확인은 별도이며, 상세 범위와 증거는 아래 인계 문서에서 확인할 수 있습니다.

일반 실행에서는 실제 공지만 표시합니다. 가상 공지는 개발자 도구와 명시적인 시연 모드에서 사용하며, 가상 데이터 테스트와 실제 수집·기기 검증을 구분합니다.

```sh
# 타입 검사·자동 테스트·포맷 검사
npm run check

# Worker 테스트와 배포 전 번들 검증
npm run test:worker
npm run worker:build

# 웹 UI 통합 테스트
npx playwright install chromium
npm run test:e2e
npm run test:e2e:release

# 플랫폼별 번들 생성
npm run build:android
npm run build:web
```

`build:android`는 Metro/Hermes 번들을 생성하며 설치 가능한 APK를 만들지 않습니다. 웹 미리보기와 UI 테스트는 Android 알림·저장소의 실기기 검증을 대신하지 않습니다.
