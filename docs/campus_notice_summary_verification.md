## 통과 조건

1. 카드에는 기회를 한 줄로 요약하고, 상세에는 신청 대상·신청 마감·행사 일시·해야 할 일을 구분한다. 필드마다 본문, 포스터 또는 첨부 파일명과 근거를 표시한다.
2. 인권아카데미의 신청 마감과 행사 시작을 바꾸지 않는다. 시간 미기재 마감을 임의로 23:59로 확정하지 않는다.
3. 같은 항목에 본문과 첨부가 다른 날짜를 제시하고 정정 근거가 없으면 확인 필요로 남긴다. 확인되지 않은 날짜는 마감 알림이나 자동 제외에 쓰지 않는다.
4. HWP를 열지 못하면 첨부 확인 필요를 표시하고 서류 항목을 만들어 내지 않는다. HWP에만 있는 항목을 실제로 추출해 파일명과 함께 표시하기 전까지 첨부 검증은 미완료다.
5. 같은 이름과 URL의 첨부 내용이 바뀌면 이전 분석을 그대로 반환하지 않는다. 재분석 후에도 저장·체크 기록을 보존한다.

### 변경 전후 검증

1. 변경 전 커밋, 계약·추출 버전, 모델, 성공 분석 예시와 게시일을 기록한다. 요약뿐 아니라 기존 태그·지원 자격·자동 알림 판정도 대조 기준에 둔다.
2. 로컬에서 npm.cmd run check와 npm.cmd run worker:build를 실행한다. Worker 테스트는 가짜 Gemini 응답을 사용하므로 실제 요약 품질 확인과 구분한다.
3. 배포 대상 설정에서 본문·포스터·HWP의 검증 사례만 선별해 Gemini로 확인한다. 정상 결과, 출처 미확인, 날짜 충돌을 비교하고 날짜·시각을 임의로 채웠는지 점검한다. 변환 대상이 없으면 검증을 통과로 기록하지 않는다.
4. 같은 공지를 다시 요청해 캐시 적중 여부를 확인한다. 새 분석을 연속 요청할 때 429면 Worker 로그의 provider_status로 공급자 제한인지 구분한다. 계정 접근이 필요한 한도·모델 변경은 운영 키를 관리하는 팀원이 확인한다. 로그·문서에 키나 시연 토큰을 넣지 않는다.
5. 계약 버전이나 추출 버전을 바꾸는 배포는 앱과 운영 Worker가 동시에 호환되도록 준비한다. 현재 운영이 단일 버전을 검사하므로 새 계약을 먼저 올릴 때 구 앱이 409를 받을 수 있다. 검증용 환경에서 먼저 확인한 뒤 운영 전환 시간을 잡고, 운영 변경 직후 호환 앱으로 공지 한 건을 분석한다. 장애 시 Worker와 앱을 서로 호환되는 이전 조합으로 되돌린다.

기존 운영 배포 및 409 복구는 [T05 인계](campus_notice_t05_handoff.md#8-e2-운영-배포와-버전-불일치-복구-2026-11-14), 앱의 재시도 대기와 SQLite 보존은 [T07 인계](campus_notice_t07_handoff.md)를 참고한다.

## 로컬 HWPX와 모의 분석의 앱 검증

897698번 실제 HWPX의 텍스트에서 추가 서류와 두 발급 연도를 확인했다. Playwright는 보관된 본교 목록·상세 HTML을 제공하고 Worker 요청에 모의 응답을 반환한다. 기존 본문 검증을 통과한 응답에 실제 첨부에서 확인한 항목, 파일명, 불일치 안내를 테스트에서 추가한다. 상세에 안내가 표시되고 메인에 저장하면 제출 항목이 체크리스트에 반영되는지 검사한다.

HWPX_SAMPLE_PATH에 원래 파일명을 유지한 첨부 경로를 설정한 후 웹을 빌드하고 tests/e2e/hwpx_sample.spec.ts를 실행한다. 환경 변수가 없으면 테스트는 건너뛴다. 추출 도구는 파일을 외부에 보내거나 ZIP을 디스크에 풀지 않는다. 실제 서버의 자동 다운로드, Worker의 첨부 근거 검증, Gemini의 첨부 요약은 후속 작업이다.

## Worker 첨부 텍스트 입력

수집 서버는 원본 파일 SHA-256과 추출 텍스트를 기존 분석 요청의 attachment_texts에 넣는다. 각 항목은 attachment_index(attachments의 0부터 시작하는 인덱스), sha256, text를 포함한다. 첨부 텍스트는 최대 두 개, 각 12,000자다. 전체 바이트 제한도 적용된다. 내용을 포함한 뒤 기존 hashNoticeContent로 content_hash를 다시 계산해서 요청한다. Worker는 분석 요청 전체의 해시를 확인하며 원본 파일 자체의 SHA-256은 수집 서버가 계산한다.

첨부 입력을 생략한 요청은 기존 1.1/e2 버전과 해시를 유지한다. 첨부 입력의 텍스트나 파일 해시가 바뀌면 분석 해시 및 공용 캐시 키가 달라진다. 첨부 전용 근거는 현재 체크리스트에만 사용하며, 단일 첨부에서 인용을 찾은 경우 Worker가 파일명을 붙인다. 첨부에서만 찾은 날짜를 자동 마감으로 확정하지 않는다. 발급일 연도 불일치는 모의 모델의 확인 안내로 검증하며, 운영 Gemini의 처리 품질은 원문 대조가 필요하다.

브라우저 검증은 실제 HWPX로 가로챈 앱 요청을 보강하고 Worker 검증 함수를 사용한다. 서버의 자동 다운로드 및 변환과 운영에 배포하는 작업은 남아 있다.

## 본교 HWPX 다운로드 연결

Workers 호환 worker/src/seoultechHwpx.ts는 본교 4691번 게시판의 상세 첨부 영역에서 학교 다운로드 폼 값을 읽고 고정된 학교 HTTPS 경로에 POST한다. 최대 5 MiB, 제한 시간 내에서 HWPX를 다운로드하며, ZIP/XML 추출기의 결과를 attachment_texts에 넣고 요청 해시를 다시 계산한다. 다운로드나 변환에 실패하면 원래 본문 요청으로 돌아가며 실패 원인을 별도로 남긴다.

Node에서 node --import tsx scripts/hwpx_collect_smoke.ts를 실행하면 보관된 897698번 상세 HTML의 첨부를 학교 서버에서 다운로드하고 분석 요청 JSON을 출력한다. 학교 다운로드 연결과 로컬 변환만 실행하며 Gemini 요청이나 운영 배포는 하지 않는다. Linux는 개발 환경이며 운영은 Cloudflare Workers가 관리한다. 추출기는 npm ZIP/XML 파서와 웹 표준 API만 사용하며 OS 패키지나 셸을 실행하지 않는다. 로컬 스모크와 테스트 또는 아래 파일럿 설정에서 호출한다.

## Cloudflare Workers의 897698번 자동 수집 파일럿

HWPX_PILOT_NOTICE_ID를 seoultech_general:4691:897698로 설정한 Worker에서, 유효한 분석 요청에만 학교 상세와 첨부를 합계 6초 이내에 조회한다. 학교로 시연 토큰이나 Gemini 키를 보내지 않는다. 설정을 주지 않으면 기존 본문 분석 경로를 사용한다. 학교 요청이나 추출이 실패해도 본문 분석으로 이어진다.

공용 캐시는 첨부를 반영한 요청 해시를 쓰고, 앱 응답은 앱이 보낸 본문 해시를 돌려준다. 기존 1.1/e2 앱 계약과 본문 캐시를 유지한다. 앱에 이전 분석이 저장된 공지는 자동으로 다시 보내지 않으므로 파일럿을 확인하려면 해당 공지의 새 분석 요청이 들어와야 한다. 첨부만 바뀌었을 때 휴대폰이 먼저 알아채는 백그라운드 감지는 아직 없다.

모의 Gemini를 사용하는 Worker 테스트와 Wrangler dry-run을 검증했다. 운영 배포와 실제 모델 검증은 키를 관리하는 팀원이 파일럿 설정을 적용하고 897698번 한 건으로 실행한다.
