## 1 변경 내용

`tests/t09Integration.test.ts`는 HTML 파서 → 수집 → HTTP AI 클라이언트 → 동기화 → SQLite → 알림 재조정을 연결한다. `fixtures/synthetic/t09.ts`의 공지는 제목에 가상 T09를 표시하며 네트워크 응답을 주입한다. 이 데이터는 실제 학교 공지나 실제 AI 응답이 아니다.

마감 변경 상태가 repository에는 있었지만 통합 상세 화면에는 표시되지 않았다. 상세에 **마감이 변경되었어요. 새 일정을 확인해 주세요.**와 **마감 변경 확인** 버튼을 연결했다. 버튼으로 확인하기 전에는 갱신·재실행 후에도 표시를 유지한다. 기존 준비물 UUID·체크·진행 상태와 새 준비물 안내도 함께 검증한다.

목록 밖 저장 공지 재수집은 저장 객체의 추가 필드가 엄격한 상세 파서 입력에 들어가 실패했다. `collectDetail`이 `NoticeRef` 필드만 전달하도록 수정하고 실제 파서·동기화·알림 연결 회귀 테스트를 추가했다. 상세 쓰기 처리 중 버튼을 비활성화해 빠른 체크·진행 상태 연속 조작이 조용히 무시되지 않도록 했다. 알림 조회·취소·예약 실패는 저장을 되돌리지 않고 화면에 재조정 실패 안내를 표시한다.

설계 13.2의 조건 판정 구현도 없었다. `evaluateEligibility` 순수 함수로 최신 분석의 명시적 불일치·미확인·복합 조건을 구분하고 카드·상세에 이유를 연결했다. 맞춤 목록에서 명확한 불일치는 제외하되 전체 보기·저장 목록에서는 계속 확인할 수 있다. 컴공 별칭만 연결하며 다른 전공·5학년 이상·기타 학적을 임의로 확정하지 않는다. 프로필 영속화·추천 정렬 고도화는 기존 T04 범위로 남는다.

`/dev/t09`는 별도 `t09-verification.db`와 `t09-verification-v1` 알림 태그를 사용한다. 제품과 같은 native 알림 어댑터·repository·수집·동기화·reconciler를 사용하되 HTML과 AI만 가상 응답으로 주입한다. 가상 마감은 실행일 기준 미래로 이동하며 기준값을 검증 DB에 보관한다. 제품 DB나 실제 공지 날짜는 수정하지 않는다. 검증 알림은 테스트 문구로 표시한다. OS 예약 직후 DB 기록 중단도 주입할 수 있다.

웹 캡처: [변경된 마감·준비물](screenshots/t09_changed_detail.png). Android 캡처가 아니다.

## 6 완료 판정

- `npm run test:t09`: 17개 통과.

workerd와 Playwright는 샌드박스의 로컬 포트 차단으로 처음 실행이 실패했으며, 승인된 환경에서 재실행해 통과했다. Chromium 경로는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/tmp/chromium`을 사용했다. 최초 웹 테스트에서 체크 직후 진행 상태 입력이 무시되는 현상을 확인했고, 상세 쓰기 중 버튼 비활성화와 상태 전환 확인을 반영한 최종 전체 실행에서 통과했다.

이후 사용자가 안내받은 Android 1~8번에 대해 “검증 완료”라고 보고해 남아 있던 실기기 인수를 마쳤다. 자동·웹·실제 Worker/SQLite 증거와 사용자 기기 확인을 종합해 T09를 완료로 판정한다. 이 판정은 실제 게시자의 공지 수정 사건 관찰, 미래 마감 시각의 알림 수신, APK 생성·배포 또는 T10 제출 완료를 뜻하지 않는다.

2026-11-14 PR 준비 시 최신 main(`9bfe3d2`, UI 변경과 B의 체크리스트·실제 알림 상태 표시 포함)을 통합했다. 새 인라인 상세·단일 카드·페이지 전환·페이지 스크롤 방식을 유지하면서 T09의 지원 조건 판정, 마감 변경 확인, 쓰기 중 버튼 비활성화, 알림 실패 안내를 연결했다. 실제·가상 카드 구분과 시각 미확인 표기도 유지했다.
